## Feature currency review — 2026-10-17

This review records concrete retain/defer decisions against the current implementation and upstream documentation. It does not imply that a feature is safe merely because the code path is present, nor that optional provider evaluations ran.

| Python and uv runtime selection | Python 3.12 and 3.13 are supported. Its later dependency-audit steps fail on unresolved advisories, tracked under R02. |
| Local vector retrieval and embedding | `Retriever` uses Chroma `PersistentClient`, cosine distance, Chroma's local ONNX all-MiniLM-L6-v2 default, corpus fingerprinting and deterministic reindexing. It does not start or connect to a Chroma HTTP server. | Chroma's [Python client reference](https://docs.trychroma.com/reference/python/client) describes `PersistentClient` as local development/testing and recommends a server-backed Chroma instance for production. The [PyPI release record](https://pypi.org/project/chromadb/) identifies the current stable package. | Local persistence keeps clean-clone evaluation self-contained, but the persisted index and embedding implementation couple behavior to Chroma. Current stable ChromaDB 1.5.9 is flagged by unresolved high/critical advisories; local-only reachability narrows some paths but does not make the scanner clean or prove the dependency safe. | **Retain only for this local fictional-policy evaluation; prohibit a production claim/deployment while security gates fail.** Existing retrieval ablation and the exact app integration test establish behavior; `pip-audit` and Trivy on `c37c41b` still fail. No finding is suppressed. Reassess a compatible backend or patched stable Chroma before any remotely exposed use. |
| Tool schema and authorization boundary | The assistant exposes one coverage-calculator schema, validates its arguments in target-owned code, rejects unexpected/multiple calls, and keeps synthetic member authorization in the application/API rather than trusting model-selected identity. | [Pydantic model validation](https://docs.pydantic.dev/latest/concepts/models/) is used for typed request/response data; the shared reference application's API checks member-scoped access independently of the assistant. | Explicit schemas and server-side scope reduce hallucinated tool and cross-member access risk. More autonomous agent loops would add state, provider variance and extra authorization paths. | **Retain the single-round bounded tool. Defer agent-framework adoption.** Shared-app run `39028982451` passes pinned-image startup, member-isolation and citation retrieval with a stubbed provider; it makes no live model-quality claim. |
| Semantic and adversarial evaluation | Semantic evaluation is optional and separates replay from provider calls. The lock currently resolves DeepEval and RAGAS; RAGAS adapters use the legacy `ragas.metrics` path and contain a compatibility shim. Promptfoo live red-team runs are separate from hermetic adversarial tests. | RAGAS [current metric catalog](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) includes RAG and tool-use metrics; the [RAGAS PyPI release record](https://pypi.org/project/ragas/) and [Chroma release record](https://pypi.org/project/chromadb/) were checked on this review date. | New metric collections and agent/tool metrics could broaden measurement, but the newer RAGAS import/adapter shapes require a real compatibility run. No extra provider call or budget was assumed. |
| Container runtime and OS packages | The image is digest-pinned, installs a full evaluation environment, and runs as non-root `appuser`. The current dependency audit is intentionally red: on 2026-10-17 direct PyPI JSON still identifies ChromaDB 1.5.9, DiskCache 5.6.3 and RAGAS 0.4.3 as latest stable releases, and the current scanners report nine Python advisory records. **R02 is not complete** until a compatible, tested remediation or formally governed, time-bounded disposition allows all required checks to complete without weakening their coverage.
